## 🛠️ The Core Database Schema
### 1. devotions
Stores the daily content pushed by the admin team.
```sql
CREATE TABLE devotions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    publish_date DATE UNIQUE NOT NULL, -- Ensure only one devotion per day
    title_en VARCHAR(255) NOT NULL,
    title_sn VARCHAR(255) NOT NULL,
    verse_reference VARCHAR(100) NOT NULL, -- e.g., "John 3:16"
    verse_text_en TEXT NOT NULL,
    verse_text_sn TEXT NOT NULL,
    reflection_en TEXT NOT NULL,
    reflection_sn TEXT NOT NULL,
    action_point_en TEXT NOT NULL,
    action_point_sn TEXT NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

```
### 2. questions ("Bvunza Pastor")
To protect the identity of the youth asking sensitive questions, we **do not** link this table to a user account ID via a foreign key constraint. Instead, it relies on an unlinked, unique ticket_id stored locally in the youth's app state.
```sql
CREATE TABLE questions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    ticket_id VARCHAR(50) UNIQUE NOT NULL, -- Generated client-side or pseudo-randomly
    question_text TEXT NOT NULL,
    category VARCHAR(50) NOT NULL, -- 'social', 'spiritual', 'economical'
    is_answered BOOLEAN DEFAULT FALSE,
    answered_by_admin_id UUID REFERENCES auth.users(id), -- Tracks which elder replied
    answer_text TEXT,
    answered_at TIMESTAMP WITH TIME ZONE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

```
### 3. prayer_requests ("Imba Yokunamatira")
Tracks community prayer focuses and individual anonymous requests.
```sql
CREATE TABLE prayer_requests (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    is_daily_focus BOOLEAN DEFAULT FALSE, -- True if posted by Pastor as a main focus banner
    request_text TEXT NOT NULL,
    pray_count INT DEFAULT 0, -- Incremented when someone taps "Ndiri Kukunamatira"
    is_answered BOOLEAN DEFAULT FALSE, -- Pastor can toggle to move it to the Answered Wall
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

```
### 4. gospel_tracks ("Nziyo dzaMwari")
Curated completely by the admins to keep storage lightweight and copyright safe.
```sql
CREATE TABLE gospel_tracks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    title VARCHAR(255) NOT NULL,
    artist VARCHAR(255) NOT NULL,
    audio_url TEXT NOT NULL, -- Points to Supabase Storage bucket hosting the compressed MP3
    lyrics_en TEXT,
    lyrics_sn TEXT,
    playlist_category VARCHAR(100) DEFAULT 'General', -- e.g., 'Ruwa Worship', 'Quiet Time'
    uploaded_by UUID REFERENCES auth.users(id),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

```
### 5. anonymous_chat_room ("Imba Yokutaura")
The group chat environment where names change to break up long-term tracking.
```sql
CREATE TABLE anonymous_chat_room (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    alias_name VARCHAR(100) NOT NULL, -- e.g., "Mukoma_Butterfly23"
    message_text TEXT NOT NULL,
    is_flagged BOOLEAN DEFAULT FALSE, -- Set to true if a youth hits "Report"
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

```

To make sure youths trust the platform entirely, apply these rules in your database backend:
 1. **Anonymous Chat Safeguard:** Keep retention low on anonymous_chat_room. Set a cron job to automatically wipe messages older than 7 days to keep performance high and prevent conversational logs from building up permanently.
 2. **The "Bvunza" Firewall:** Because there is no link between the questions table and the user authentication profile table, even an admin with direct database access cannot look at a row and see who sent it. They can only see the text and the random alphanumeric ticket identifier.
 3. **Admin Exclusivity:** Ensure that write/insert permissions on devotions and gospel_tracks require an authenticated session token carrying an explicit admin claim metadata flag.
